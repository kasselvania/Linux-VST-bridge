# SHIELD XL native physical loopback, 2026-09-24

At 20:22:49 UTC the operator-confirmed cable fixture connected SHIELD XL
output 1 to input 1 and output 2 to input 2. JACK was 48 kHz / 128 frames;
ALSA reported S16_LE stereo, period 128 and buffer 384 for capture and playback.

The existing Rust qualification instrument was built on the Pi with
`rustc --edition=2021 -O rpi1/qualification.rs`. Its added `loopback` mode
emitted independent, deterministic stereo broadband signals below -40 dBFS
for one second inside a three-second recording. Generation/allocation happened
before activation and file writes after callback retirement. Digitalis kept
running but its four physical JACK connections were temporarily removed.
The probe disconnected its own ports; all original connections were restored
and the complete JACK graph compared equal to the pre-test graph. No plug-in
parameter, preset, bypass, runtime limit or buffer setting changed.

## Observed result

| Path | Peak-correlation delay | Correlation |
| --- | ---: | ---: |
| SHIELD output 1 -> cable -> input 1 | 552 frames / 11.50 ms | 0.81794 |
| SHIELD output 2 -> cable -> input 2 | 552 frames / 11.50 ms | 0.81969 |

Both captures contained 144,000 frames. Zero JACK xruns, malformed blocks
or nonfinite samples were reported. Cross-channel matches were rejected
(correlation about 0.018). This is one short measurement, not a stability run.
The estimator reports integer-sample correlation peaks, not a sub-sample
converter group-delay estimate.

The analysis self-test recovered 534- and 18,384-frame delays with attenuation,
polarity inversion and added noise; silence and unrelated noise were rejected.
All nine Rust fixture tests passed. A separate negative run with Digitalis's
physical routes restored refused before activation and left the graph unchanged.
The installed instrument digest and exact live-build source digests are in the
JSON receipt; only a `cfg(test)` stimulus-bound test was added after that build.
Run it with `python3 rpi1/loopback_analysis.py --self-test` (NumPy required).
Analyze a retained return using `python3 rpi1/loopback_analysis.py RETURN.f32le`;
the sent reference must be alongside it as `RETURN.f32le.input.f32le`.

## Comparison with operator measurements

The operator reported approximately 383 ms through the pedal and 284 ms
through a direct MOTU output-to-input cable loop, confirming the same Bitwig
buffer and that the pedal was outside the second loop. These are operator
observations, not measurements generated by this probe.

Their difference is approximately 99 ms. The new SHIELD measurement plus
Digitalis's previously reported 4,096-frame latency and the 128-frame bridge
reserve is `552 + 4096 + 128 = 4776` frames, or **99.50 ms** at 48 kHz.
This closely supports a roughly 99 ms incremental pedal delay and places the
large baseline in the Mac/MOTU test path. It does not identify whether that
baseline arose in Bitwig compensation/calibration, Core Audio, the driver,
interface routing, or another part of that measurement path. It also does
not erase previously recorded bridge gaps at 128 frames.
