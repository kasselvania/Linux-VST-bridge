# Pinned-runner Linux lead qualification

A project-owned Windows PE named `NTKDaemon.exe` ran in a fresh disposable prefix
under the exact registered pinned runner and a dedicated cgroup. This is a process
lead fixture, not the vendor daemon and not service-readiness evidence.

The exact generated image exposed all four admitted Linux leads: stat comm, comm,
NUL-delimited command token and mapped PE basename. Its Linux PID/start generation,
image digest/size/architecture and same-prefix relation were established independently
of Windows PID numbers. Wrapper command-token leads remained ambiguous; they were
not promoted to daemon identity. Unrelated unreadable processes did not weaken the
census. Cleanup was positive, the unit retired and the disposable prefix was removed.

The retained proof and package seal identify the executed source generation. The
later production owner relocates the same census implementation into the installed
ownership artifact; it does not infer vendor process authority from the fixture.
