# Recover the qualified existing daemon without reinstalling

The original real installation failure remains unchanged. This amendment permits
the existing parameter-free Prepare action to qualify the already-installed exact
bundle payload through SCM readiness rather than rejecting it forever or rerunning
its installer. It does not reinterpret Windows installer exit 100 as success.

Production admission is limited to the committed bundle/member qualification and
exact sources of the retained failed operation. Both Rust and Python verify the
historical source hashes and current payload. Python additionally verifies the
same application/environment and prior clean retirement. No arbitrary executable,
service, arguments, environment, prefix or historical operation is accepted.

Recovery uses query/start/readiness/stop/query. It cannot install, adopt a foreign
or unowned process, accept an open port without exact service/process ownership,
or create a readiness receipt on failure. Missing registration refuses without
reinstalling. Successful readiness plus clean service/process retirement produces
an ordinary new preparation record. Subsequent Native Access launch still checks
fresh readiness. Neither renderer policy nor audio paths change.
