# Implementation review

```text
Review the actual code and relevant tests/results against the requested
outcome. Check correctness, SDK ownership/threading, audio-callback behavior,
failures and cleanup where affected. Confirm the evidence covers the code
being delivered and state what you did not independently reproduce.

Accept bounded working behavior or identify concrete repairs. A missing
procedural receipt is not a product defect. Request additional testing only
for a specific uncertainty; do not rerun successful work just to rename it
acceptance. Review and merge only within the operator's permission.
```
