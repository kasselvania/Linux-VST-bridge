# AP1 mapped round-trip contract — output-silence repair

The existing Windows host keeps one AGain instance and one borrowed mapping alive for a native Linux Rust caller. This is an offline x86-64 Linux/Wine fixture contract. AP0 and PC0 remain accepted and their modes/evidence are unchanged.

## Bytes and ownership

All fields are explicitly little endian. Control headers are 56 bytes: magic u32 `0x3141504c` at 0; major/minor u16 at 4/6 (1/1); kind/flags u16 at 8/10; payload length u32 at 12; session bytes[16] at 16; instance u64 at 32 (1); sequence u64 at 40; parent u64 at 48 (0). Flags are zero. Header plus payload never exceeds 4096 bytes. Kinds are Hello=1, Ready=2, Process=3, Done=4, Close=5, Closed=6, Error=7. Unknown versions/kinds/flags/parents/instances and invalid lengths fail closed.

One private 4192-byte file in the owned session tree is mapped read/write with Linux MAP_SHARED and Windows CreateFileMapping(PAGE_READWRITE)/MapViewOfFile(FILE_MAP_READ|FILE_MAP_WRITE). Its 64-byte header has eight u32 fields: magic `0x4d315041`, layout 1, capacity 256, channels 2, size 4192, input offset 64, output offset 2128, channel stride 1032. Two input and two output regions each contain 258 float32 words: a leading guard, capacity 256, a trailing guard. Guards are `0x4b123456`; unused output words are poisoned with `0x7fc12345`. No peer-supplied offset/stride can change these regions.

The native client creates the file and an OS-selected IPv4 loopback listener. An owner-only launch file supplies the port, session and a fresh 32-byte capability to Windows; neither secrets nor network coordinates enter retained diagnostics. Windows sends Hello with capability[32], capacity u32 and mapping size u32. Before this it reads a Linux-chosen u64 at mapping offset 32, XORs `0x8d396b274e105ac3`, and writes the result at 40. Linux authenticates Hello and checks that mapped witness, writes the witness XOR 1 at 56 and replies with empty Hello. Windows validates it before module activation. After activation and processing-thread start it sends empty Ready. This establishes actual bidirectional same-file visibility before audio.

Process has a 32-byte payload: frames u32 at 0, input/output/stride u32 at 4/8/12, normalized finite gain f64 at 16, input silence flags u32 at 24, reserved zero u32 at 28. Frames are 1–256; gain is [0,1]; silence flags are 0–3. Done contains frames and output offset, both u32, then the actual output silence mask as u64 (16-byte payload). Version 1.1 rejects the earlier 1.0 frame format; mapping layout stays 1. Output masks may differ from input masks. Bits outside the two declared channels are rejected; each flagged channel must contain only numerical zeros (including signed zero). Unflagged channels may be zero. The native result handler checks before mapped publication, and Linux retains the actual mask and independently checks it with returned samples. The full 64-bit SDK mask is preserved without narrowing. Close/Closed are empty. Error contains a bounded reason code and makes the session unusable. Hello/Ready use sequence zero; Process starts at 1 and strictly increases, at most 64 blocks; Close uses the next sequence.

Only one block is outstanding. Linux writes input/poison, publishes Process, then holds the slot inaccessible until an exact matching Done. Windows snapshots validated request metadata and copies input to preallocated private SDK buffers; checks private input, guards and unused output; writes only the requested shared output extent; fences and sends Done. Linux checks actual mapped words, never a host-reported PASS or control-channel audio payload. No per-block file IO or remapping is used.

Both handoffs use compiler barriers plus a full x86-64 hardware fence (Linux mfence; Windows MemoryBarrier and compiler intrinsics) before publication and after receipt. These combine the explicit sole-writer ownership transfer with coherent same-file mappings on this measured fixture. Socket order or volatile alone is not the memory model. No Rust references into the view survive an access or handoff; mapping reads/writes copy through checked raw-pointer operations. No shared language-atomic object ABI or lock-free/portable-memory-model claim is made.

## Fixed discriminating verification

Only after Windows Ready, Linux reads a fresh reproducible u64 seed. It keeps the seed; it sends Windows only samples and request metadata. The original eight requests retain lengths `[1,16,63,256,16,63,1,256]` and gains `[0.5,0.25,0.75,0.5,0.75,0.25,0.5,0.75]`; index 5 is all-channel silent. Two additional requests use 16 frames/gain 0/input mask 0, then 63 frames/gain 0.5/input mask 1. Their inputs are respectively ordinary non-silent stereo and correctly zeroed left-channel silence with nonzero right-channel data. All ten input masks are `[0,0,0,0,0,3,0,0,0,1]`. For block b/channel c, x starts as seed XOR ((b+1)*0x9e3779b97f4a7c15 modulo 2^64) XOR ((c+1)<<48). For each sample apply xorshift (<<13, >>7, <<17) modulo 2^64; input is `(x mod 129 - 64)/128`, except channels selected by the input silence mask contain zeros. In appended block index 8, sample zero is fixed to `(c+1)/4` to ensure non-silent input for every seed. In appended block index 9, right sample zero is fixed to -0.5; left remains zero. The original eight recipes are unchanged. All values/products are exactly representable binary fractions. Bypass is zero through SDK gain/bypass queues; no musical events.

Linux retains actual request/input/output words and checks every one of 1502 returned samples, unchanged inputs/guards and unused capacity. Expected values derive from Linux's request and seed, never returned gain or output. Absolute tolerance is zero; signed zero compares numerically. Missing, stale, swapped, unwritten and nonfinite outputs fail the whole batch. Python independently rechecks the retained mapped data against the same documented mathematical contract.

## Deadlines and retirement

The client listener has a 180-second setup deadline, matching the existing outer readiness watchdog. Hello IO is at most 10 seconds on Linux and 5 seconds on Windows; Ready at most 15 seconds. Each Process/Done IO operation has a 5-second absolute deadline across fragments; Close/Closed at most 10 seconds. Existing outer 15-second plug-in-call, 120-second post-gate and owned-process cleanup bounds remain enforced. No timeout/disconnect/invalid response is retried or reconnected; outstanding outcome remains failed/unknown, earlier complete observations survive, and no partial batch becomes successful.

Close is admitted only without outstanding work. The processing thread stops and joins before owner-thread deactivation, interface/component retirement and DLL unload. Windows unmaps/closes its borrowed handles before Closed. Linux then closes its view and connection. The existing supervisor owns both process groups, retains checkpoints before cleanup, proves both endpoints absent and only then removes the backing file with the owned stage. Unknown containment prevents retirement or new live work. No protected fixture/runtime files are changed.
