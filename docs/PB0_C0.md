## Interactive and deep authority

`operator overview` returns a versioned current-only envelope paired to operator schema 12. Its dedicated `CurrentOverviewContext` captures current software, registry, installed profiles, capacity, products, Setup and workspace summaries. It verifies shared artifact/environment/runner identities once per unique item, retains only current revision facts, and excludes preparation, publication, incident and operation histories. The resolver consumes this captured context without reopening manager authority; a final token, owner, generation and watched-artifact recheck refuses drift before return. The ordinary full `operator snapshot` retains deep histories for Details and Diagnostics.

`operator pulse` is a change detector, not a cleanup or readiness certificate. It reads service state, bounded owner counts, pending count, latest operation and a current-generation fingerprint without running the full capacity or incident readers. The frontend polls and redraws at ten-second idle cadence or two-second live-operation cadence, refreshes the overview on relevant change, and expires a current overview after 60 seconds even if no pulse detects external drift. It shows the shell before fresh readback, disables actions when freshness is lost, and loads full Snapshot only on a technical page. Home/Setup actions are admitted from the current exact offered set and token, then rechecked by their target owner at the mutation boundary. The source-owned Setup fixture obtains a durable acknowledgment without a Diagnostics Snapshot. Private schema-11 requests remain historical recovery input only.

The collector reads a fixed set of bounded platform facts: architecture, model, distro/version, kernel, graphical session and local X11 socket, Bitwig Flatpak identity/permissions, user runtime and PipeWire/JACK availability, and PipeWire graph rate/quantum. Typed probe results distinguish observed absence from unavailable or malformed observation. Fixed helpers use an owned process group, bounded output and a deadline; timeout, overflow and completion retire descendants before the read returns. Device sample rate and Bitwig callback maximum remain unknown without a trusted live adapter; graph metadata cannot prove them. No arbitrary process dump, home traversal, credential, authorization payload, proprietary state or license material is collected.

The resolver derives support from captured canonical registry, exact accepted profiles, installed software and physical publication verification. Documentation is never parsed as live policy. The initial ordinary support envelope is the exact three Arturia profiles described in `PRIVATE_BETA.md`. Each product separately reports current installation health and beta support qualification: an unqualified product can still be healthy or need repair. An intentionally removed publication can be physically consistent without being ready for Bitwig. An unsupported product does not make the platform unsupported. Unreadable registry/profile authority is an explicit authority failure.

The local support export requires the manager's currently offered `SupportExport` action and a fresh schema-12 token. The server rederives the offer before execution. Its separate schema-2 support DTO excludes live tokens, offered actions, action arguments and freshness authority. It labels selected software generation, manager/frontend digests, package version and manager source version separately, then includes allowlisted readiness, safe artifact/profile identities, categorized errors and bounded sanitized incident summaries. No output path, command, PID, network upload, prefix dump or unrestricted log enters the action.
