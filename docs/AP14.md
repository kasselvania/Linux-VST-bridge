# AP14 — Profile-driven managed publication and rollback

Implementation candidate for issue #83 / draft PR #85, based on integrated AP13 `ca0e2f7d5c85515c8ec22b67d434c6288ca611f7`. Exact Deck workflow verification is in progress; this document does not yet claim completion. AP13 audio/state/delivery results and AP12 commercial evidence remain unchanged.

## Ordinary installed operation

Product setup installs `~/.local/bin/linux-vst-bridge`. The command operates on the existing owned Arturia environment:

```text
linux-vst-bridge managed environments
linux-vst-bridge managed preview
linux-vst-bridge managed publish
linux-vst-bridge managed status
linux-vst-bridge managed rollback PRODUCT_NUMBER EXACT_RETAINED_REVISION
linux-vst-bridge managed reconcile
```

An environment number is required only when selection is ambiguous. Product numbers and retained revision IDs come from structured status. The ordinary publish operation discovers installed modules, performs supervised inspection when its exact census is absent/stale, matches embedded profiles, derives registrations and publishes both supported classes. It accepts no caller-supplied class ID, digest, compatibility boolean, registration JSON, native build path or runner command. The old raw registration command remains a development surface and refuses changed or managed bindings.

## Profile and artifact contract

`compatibility/arturia-pure-lofi.json` and `arturia-efx-fragments.json` are schema 1, immutable revision 1 candidates. Their claim remains `review_candidate` pending independent technical review. Exact observed module SHA-256, vendor, SDK class name/version/subcategories/tier and instrument/effect role bind each match. Requirements separately pin the runner's critical artifact set and entry points, environment family/revision, Windows host/source manifest, native image/source commit and generator descriptor hash.

Capabilities are closed Rust enums: process-scoped disabled Windows accessibility; the existing detached vendor window with native open/close panel; AP13 concurrent read-only state capture; float32 only; 512 recommended with 256 unqualified. Profiles contain no commands, arbitrary capability maps, local environment IDs/paths, vendor state or authorization material. Evidence references are bounded, relative, non-authoritative paths. Input is limited to 16 KiB per profile, 16 profiles, fixed typed nesting, bounded strings and collections. Unsupported schema/capabilities, unknown fields and duplicate identities/revisions are refused before scanning/publication.

The bounded AP14 native route adopts the existing exact, already owned generated proxies during product software setup and verifies them against the pinned profiles. It installs copies and an exact catalogue with immutable product software. Subsequent publication does not depend on the original generator checkout or build tree. This is not a native compiler/download service for unknown products. The native binaries and Windows host are reused; their original AP13 source/artifact identities remain distinct from the AP14 manager identity.

Supervised census uses the existing Windows factory/inspection code and installed owner service. A coordinated inspection excludes DSP admission while sharing the persistent environment keeper. Internal standalone inspection retains exclusive locking. Factory Windows TUIDs are normalized to portable SDK FUID strings; only the selected declared audio-module class is matched. Parameter metadata completeness is checked without making successful parameter value readback or state saving a prerequisite. Cached normalized observations are checked against the exact retained supervised report, current module stamp/hash, environment/runner/host and a ten-minute freshness bound.

## Publication and recovery contract

The existing registry, owned bundle store and DAW discovery link remain authoritative mechanisms. Registry entries add an optional exact managed revision reference. Each immutable revision binds the profile/claim, exact census, registration, stable external IDs, performance selection, native target, transaction and parent. Legacy adoption records the exact existing target as a retained parent; it does not reconstruct it from mutable source files.

A durable intent records prior and candidate before candidate creation and activation. The candidate native image, bundle provenance and revision record are exact and fsynced before the discovery link changes. Linux uses `renameat2` exchange/no-replace; macOS fixture tests use the corresponding exclusive/exchange primitive. Displaced links are checked and foreign entries are preserved. Registry commit and result retention follow the pointer exchange. Recovery reads the durable intent and physical link: prior still active means abort, candidate active means validate/complete, and an invalid activated candidate restores the recorded intact prior. Results are retained and cleanup is repeatable.

Rollback selects an exact retained ancestor and refuses incompatible current module/runner or performance bindings. It never rebuilds an old target. Active target DSP leases block publication, removal and rollback; a keeper or healthy sibling does not. A failed operation can retain inactive candidate/staging files as diagnostic artifacts; AP14 does not implement a general history garbage collector. Same-user tampering is detected through hashes/physical checks; this is not a security sandbox against the account that owns the files.

Canonical Rust status reports physical versus recorded publication, exact profile/claim, module/build and environment/runner/host/native validity, prior rollback target, selected performance, capabilities, limitations, pending recovery and typed refusal. Missing files are failures, not positive status inferred from registry intent.

## Focused verification

Production-path tests cover strict profiles, exact/zero/ambiguous matching, class/role/metadata mismatch, stale or changed census/module, wrong runner/environment/host/native, unsupported precision, derived registration, stable UUIDv5 identities, installed artifact independence, idempotent publication, independent classes and DSP lease refusal. Transaction injection covers sixteen durable boundaries, plus rollback/removal boundaries, corrupted activated candidates, exact prior preservation, foreign entries and physical readback. Linux process tests retain AP12/AP13 ownership, failure visibility and positive retirement coverage; coordinated inspection adds a focused lock-mode regression.

`managed check-candidate PROFILE` is a diagnostic refusal preview and cannot activate caller-authored profiles. `managed fault-check PRODUCT_NUMBER` injects only the fixed candidate-ready-before-activation boundary against disposable candidate files; normal reconcile leaves the recorded prior active. All post-activation injection remains in deterministic fixtures.

Local/CI/Deck results and installed publication identities will be added after the exact candidate checks. No new latency qualification is claimed. **512 frames remains installed, supported and recommended; 256 remains unqualified.** Editor panel behavior, runtime, vendor artifacts, licensing posture and project bindings are preserved. Issues #80 and #84 remain outside AP14.
