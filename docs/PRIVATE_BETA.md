# Private beta product contract

**Status:** proposal, not a release or payment offer. The first paid-value
hypothesis is that a musician will pay **$30** to get one exact supported
Windows plug-in into a supported native Linux DAW without routine Wine,
prefix, runner, proxy, publication or recovery administration. The purchase
would buy the manager workflow, tested compatibility knowledge, bounded
diagnostics and rollback for declared configurations, plus beta support. It
would not buy vendor installers, plug-in licenses, credentials or a guarantee
for an undeclared machine.

## Initial exact support proposal

| Lane | Machine and DAW | First products | Required posture |
|---|---|---|---|
| Native x86 Linux VST3 | Steam Deck Galileo, SteamOS 3.8.16, Desktop Mode with XWayland, Bitwig Studio 6.1 Flatpak `app/com.bitwig.BitwigStudio/x86_64/stable` | Arturia Pure LoFi 1.0.0.6121 / class `417274754156495350724C4650726F63`, Efx FRAGMENTS 1.0.0.2925 / class `41727475415649536772616E50726F63`, Pigments 7.0.1.6772 / class `41727475415649534B61743150726F63` | Exact ordinary verified profile revisions 10, 10 and 18, respectively; verified module/runner/host/proxy/publication; 48 kHz device rate, Bitwig callback maximum at most 512 frames, 512 added bridge frames. |

Those profile revisions pin runner
`proton-11.0-2c-25118279-slr4-4.0.20260805.254769` and their own
module, host/source, native proxy and descriptor digests. The installed
catalogue and physical publications must match; this table does not substitute
for that verification.

PB0 cannot read Bitwig's callback maximum or the physical device rate from an
idle manager. It therefore reports `action_required` for that part of even an
otherwise exact Deck fixture. A musician can inspect Bitwig's settings, but
PB0 does not treat that manual inspection as canonical proof; PB2 owns a
supported post-change verification path. PipeWire graph rate is recorded only
as graph metadata.

The first staged PB0-C0 Deck overview reported exactly that `host_audio`
action but missed its speed target at a 10.528-second median. The focused
read-only repair measured a 1.393-second warm median and a 2.039-second maximum
with the same truthful result. The paired build is **not installed**. The
[first](../evidence/pb0-c0/deck-readonly-2026-09-28.md) and
[repaired](../evidence/pb0-c0/deck-readonly-repair-2026-09-28.md) receipts
separate source/staged timing from future installed first-run acceptance.

The source-owned PB0 resolver binds these rows to exact immutable installed
profiles and current physical readback. The other selected Deck products have
their own accepted experimental results in [SUPPORT_MATRIX.md](SUPPORT_MATRIX.md),
but they are outside this first ordinary-profile beta envelope. Ubuntu
FRAGMENTS has a separate accepted fixture with a required workaround; it is
not inherited by the Steam Deck envelope or included in this first beta row.

## User journey

1. Open the manager. It identifies the machine, DAW, current service and exact
   product artifacts. Each fact states its source and certainty.
2. Read one truthful outcome: ready, action required, unsupported or unknown.
   The Home outcome describes the machine and DAW lane; a withdrawn,
   quarantined or unqualified plug-in retains its own status and cannot erase
   another product's verified support. Unreadable registry or installed profile
   authority is a distinct unknown failure, not an unqualified product.
   Unknown combinations are not called incompatible or supported.
3. Follow one bounded next step. Lawful vendor login remains in the vendor UI;
   the manager never handles credentials. PB1 must prove the full installer to
   first-sound journey before this becomes a release promise.
4. Refresh after an external change. Manager actions remain exact and typed;
   a stale request refuses rather than being guessed or submitted twice.
5. If something fails, use diagnostics, exact recovery/rollback and an
   explicitly created local support export. No automatic upload occurs.

## Measurable beta decision

- **Value:** at least 8 of the first 10 users reach an audible, saved and
  reopened supported plug-in within 45 minutes without maintainer SSH.
- **Truthfulness:** zero known false-ready claims; record unknown observations
  and mismatches separately from accepted negative boundaries.
- **Recovery:** each induced drift in PB3 either reaches the exact safe repair
  or a clear blocked reason while preserving the working predecessor.
- **Support cost:** a sanitized export plus user description should identify
  the first useful failure and next owner in at least 8 of 10 support cases
  without requesting the full Wine prefix or remote machine access.
- **Privacy:** zero credentials, license payloads, proprietary state, full
  home paths or unrestricted logs in support exports; creation is local and
  explicit.

Collect time to first sound, number of manual terminal/SSH interventions,
failed or uncertain operations, false-ready incidents, rollback outcomes and
support time. Do not infer a product success from installer completion alone.

## Nonclaims and support posture

No universal plug-in, distro, DAW, GPU, audio hardware or license-channel
support is promised. Vendor authorization is user owned. Compatibility is
bound to exact identity and evidence, not a name match. A source build or
published proxy alone does not establish audio, editor, state recall or
continuing use. PB0 does not change audio settings, install software, repair
unknown configurations, or collect cloud telemetry. Support exports contain
an allowlist of readiness facts, safe identities, categorized state and
sanitized incident summaries. Sensitive vendor data stays local and excluded.

## Ordered follow-on slices

1. **PB1:** one guided, no-terminal lawful install to first sound for one
   exact supported product on one exact supported machine.
2. **PB2:** coherent audio configuration and post-change verification,
   distinguishing device rate, host maximum, bridge quantum, reserve and
   vendor-reported latency.
3. **PB3:** deliberate drift, repair, update and rollback exercises; prove
   the support export is sufficient without maintainer machine access.
4. **PB4:** one second x86 Linux platform adapter and bounded migration/rebuild
   workflow, then the private beta cohort.

Each slice needs its own exact fixture and acceptance. None extends PB0 by
implication.
