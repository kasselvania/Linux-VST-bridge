# K8I1 — Exact Kontakt 8 MSI diversion and verified deployment

## Selected claim

For the exact Native Instruments **Kontakt 8 Player 8.13.1** package, the managed
Native Access session may divert the setup wrapper's one
`MsiInstallProductA`/`MsiInstallProductW` transaction into a source-owned,
package-derived deployment transaction. The wrapper receives success only after every
selected payload byte and every required Native Instruments product-state value has
been committed and independently verified. Any failure rolls back the transaction and
terminates the exact setup generation with Windows error 1603.

This is a Kontakt-specific compatibility adapter. It is not a replacement Windows
Installer, an arbitrary hook facility, or authority for another product or package.

## Components and owners

### Manager

The manager admits the exact package and immutable software generation, creates an
operation/nonce-bound private transaction directory, and projects the fixed K8I1
authority into the renderer specification. Caller input cannot select a hook command,
service, Wine prefix, destination, registry key, package, or product record.

### Renderer session

The existing NAO1 renderer owns Native Access, NTKDaemon, the Kontakt setup, the shim,
the deployment worker, and cleanup inside one renderer unit/cgroup. It installs the
per-application DLL override only for `Kontakt 8 Setup PC.exe`, arms exactly one
private request/result handoff, and restores the prior override and DLL state at
session retirement.

### Windows forwarding shim

A 32-bit source-owned `msi.dll` exports the exact names and ordinals of the pinned
Proton Wine `msi.spec`. Every export except `MsiInstallProductA` and
`MsiInstallProductW` forwards to the patched, exact `msi_lvb_real.dll`. The two selected
exports forward normally unless all closed setup/package/operation facts match. One
matching call writes one request and waits for one result for a fixed bound.

The shim contains no network client and no general command runner. A failed, malformed,
duplicated, timed-out, or adverse result terminates the exact setup process with 1603.
It never returns success merely because the request was accepted.

### Deployment worker

The source-owned worker accepts exactly one request from the exact setup process
generation. It validates the operation, nonce, request ordinal, package path and hash,
setup identity, renderer cohort, physical prefix, and immutable K8I1 authority before
building or applying a plan.

The pristine MSI and staged `OFFLINE`/FileBag are layout authority. The rewritten MSI
is observation evidence, not file-layout authority. The plan binds the relevant
`Directory`, `Component`, `File`, `Feature`, `FeatureComponents`, `Registry`,
`InstallExecuteSequence`, `CustomAction`, `CreateFolder`, `RemoveFile`, and `Shortcut`
facts. Service, class, type-library, environment, and the other separately listed
mutation-bearing tables must be empty or absent in this initial adapter. Silent
omission is refusal.

The private adapter sealer requires the exact setup, pristine MSI, rewritten MSI,
staged OFFLINE tree, and a fresh `msidump` IDT projection. It rehashes the three
package images and every selected source file, recomputes the complete table snapshot
and row counts, and refuses any nonempty mutation-bearing table not implemented by
this slice. These checks bind a reviewed private plan to the exact package inputs;
they do not, by themselves, derive or prove every destination and custom-action
disposition. The adapter remains unsealable until a package-specific plan compiler or
an equivalently exact independently reviewed derivation validates those relationships.
No proprietary table projection or payload is committed to this repository.

## Closed state machine

1. `unarmed`
2. `armed` — exact shim, real MSI library, per-app override, authority and handoff are
   installed for the renderer operation
3. `intercepted` — exactly one exact setup generation submitted one A/W request
4. `planned` — all selected files, destinations, product state, omissions, free space,
   and rollback targets are exact
5. `staged` — every source file was hashed and staged on the destination filesystem
6. `committing`
7. `verified` — payload, registry/product state, standalone, and VST3 identities match
8. `reported` — shim has received the durable terminal result
9. `disarmed`

Every fallible transition has a retained adverse state. `verified` is the only state
that authorizes the shim to return `ERROR_SUCCESS`.

## Selected installation set

- Kontakt standalone: required
- Kontakt VST3: required
- Native Instruments common engine/support files selected by those features: required
- package-derived Kontakt product record and NI registry state: required
- AAX: intentionally omitted
- licensing tokens, serials, activations, cookies, and account state: never created,
  copied, inferred, or logged
- shortcuts and documentation: classified from package data; any required item is
  handled, and any optional omission is explicit

Every required file has exactly one source, one destination, one size, and one SHA-256.
An unresolved or ambiguous source, destination, property, custom action, or required
state value refuses before mutation.

## Transaction and rollback law

Before mutation, the worker verifies every source, available space, destination-root
custody, and an exact rollback manifest. It stages every new file under an
operation-owned root on the destination filesystem. Existing destinations are copied
to the rollback root and hashed; absence is recorded explicitly.

Commit uses atomic replacement where the filesystem permits it. Each installed file
is rehashed. Product records and registry values are written from package-derived,
fixed K8I1 data only after file staging succeeds. The worker then reopens and verifies
the standalone and VST3 files and all required state.

On any failure it restores replaced files, removes files and values created by this
operation, removes the operation's product record, verifies rollback, retains private
evidence, and returns failure. It does not alter unrelated prefix or user content.

## Terminal truth

The result keeps these axes independent:

- Native Access application session: `completed | cancelled | failed`
- Kontakt installer transaction: `completed | failed | not_attempted`
- Kontakt payload verification: `verified | absent | incomplete | unavailable`
- NI product recognition: `installed | not_installed | unavailable`
- dependency cleanup: `graceful_service_retirement | exact_owned_session_cleanup |
  cleanup_unconfirmed`

Native Access UI text, wrapper exit, zero live processes, an uninstall key, or cleanup
success is never installation authority.

## Required proof

Generated qualification crosses the production manager authority, renderer protocol,
shim, plan validator, transaction, rollback, terminal parsing, and frontend. It
proves exact A/W interception, forwarder completeness, ordinal fidelity, one request,
no arbitrary execution/network import, exact package refusal, complete mapping,
source/destination hash equality, rollback, no false product record, retryability, and
independent result projection.

One disposable-prefix proof is required before managed-prefix use. It uses the exact
retained package and existing runner/session topology, requires one interception, and
verifies the complete selected payload and product state, Native Access recognition
after refresh and cold reopen, standalone launch, VST3 enumeration, and cleanup. A
forced deployment failure must leave no partial payload or product marker and must
remain retryable.

The managed NI prefix is not mutated until that disposable proof passes and a separate
review authorizes the exact operation. Direct application interaction remains with the
operator.

## Nonclaims and hard boundaries

K8I1 does not claim general MSI compatibility, general InstallAware compatibility,
another Kontakt release, Kontakt authorization, audio correctness, VST3 bridge
correctness, or reliable NTKDaemon shutdown. It does not patch the entire Proton
runner, switch Wine versions, replay another installer, synthesize licensing material,
or expose arbitrary commands. It does not permit another Native Access Install click
until the source review and disposable proof gates are satisfied.
