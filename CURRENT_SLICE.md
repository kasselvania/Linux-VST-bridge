## Selected outcome

Bring Serum 2 into the current managed compatibility platform as the first
post-Arturia vendor. Establish one lawful, exact, operator-usable path from vendor
installation and authorization through managed discovery, an inactive candidate,
and one bounded Bitwig load with note audio and the real authorized editor.

This is not a fresh bridge architecture, a yabridge pivot, a broad runner contest,
or the full Serum qualification campaign retained in issue #77. SV1 establishes
managed admission and lawful editor access. Preset, automation, save/recall,
same-instance close/reopen and ordinary promotion follow only after this checkpoint
is independently reviewed.

- a runner change supplies authorization.

Preserve ordinary Pigments18 with rollback11, LoFi10 and FRAGMENTS10, all inactive
candidate history, projects, Arturia authorization, MF1, IF1/IF2, CA1, UIO/UIR
infrastructure, 512 recommended and 256 unqualified.

  or an unmanaged/yabridge path;

Retain the historical Serum class `56534558667350736572756D20320000` and old

If no lawful installer or registered product access is available, stop with that

## Phase 3 — lawful authorization

Authorization belongs to Xfer and the operator.

Preferred path:

1. launch the exact managed Serum instance/editor;
2. stop for operator login or browser authorization;
3. retain only success/failure posture, stable nonsecret machine identity facts and
   operation cleanup—not credentials, cookies, license payloads or account pages.

The official offline path using the machine ID and a vendor-produced license file
is acceptable when the online handoff cannot operate. The operator must obtain and
supply that file through the official account flow. Do not fabricate machine IDs,
copy authorization from another prefix/machine, patch checks, intercept secrets or
bypass activation limits.

Make the managed machine identity stable across ordinary relaunch. If authorization
fails, retain the exact browser/localhost/offline boundary and stop. Do not repeat
login attempts as a test campaign.

## Phase 4 — exact discovery and inactive candidate

After installation/authorization:

- rescan through the managed scanner;
- retain the complete factory result and exact instrument class;
- distinguish the instrument from any FX or auxiliary class;
- derive a new immutable `review_candidate` profile from current evidence;
- use current shared kernel capabilities rather than copying the old AP8 descriptor;
- select product-specific buses, events, state, accessibility and runner policy only
  from current inspection evidence;
- preserve exact native and Windows host identities and rollback/nonpublication.

The candidate may be staged and selected reversibly for one bounded check. It must
not become an ordinary publication in SV1.

## One bounded product check

After generated and manager verification passes:

1. preserve canonical before-state and protected project hashes;
2. select the exact Serum candidate reversibly;
3. arm CA1 only if the candidate path supports it without broadening the test;
4. launch Bitwig normally from Applications with a disposable protected project;
5. add one Serum instrument instance;
6. verify one note produces nonzero routed audio;
7. open the real editor once;
8. complete operator-owned authorization if still requested;
9. verify the editor displays the normal authorized product surface rather than the
   authorization gate;
10. exercise one safe, known control once only if authorization succeeded;
11. quit/remove normally and confirm positive retirement and cleanup;
12. return the candidate inactive pending review.

Use Luna through the established Moonlight route only for bounded noncredential GUI
actions. The operator owns login, browser/account, license-file selection and any
purchase-related interaction. Astra is an escalation only for novel visual
ambiguity after Luna stops; neither agent may improvise authorization.

Stop after the first exact material failure. Do not run preset, automation,
save/recall, resize, touch, performance, multi-instance or buffer campaigns in SV1.

## Completion and handoff

SV1 is complete when one of these exact outcomes is retained:

### Managed authorized first load

- exact current Serum product/version/module and environment identified;
- official installation and authorization completed;
- manager shows Serum as installed with exact status;
- inactive candidate created from current evidence;
- one note produces audio;
- real authorized editor opens and one control responds;
- normal cleanup; candidate restored inactive.

### Exact operator/vendor boundary

- no bypass or repeated attempt;
- manager/product state remains safe and unchanged.

### Exact compatibility boundary

- installation and authorization succeed, but discovery, admission, audio or editor
  stops at one retained generic boundary;
- no speculative runner/profile workaround and no blind repeat.
