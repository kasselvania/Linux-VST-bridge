## Implement the ordinary VST3 return path

Use the pinned SDK's ProcessData contract, not another fixture-specific exception. Keep discovered bus metadata, implemented support and host-selected activation distinct. A default-inactive flag does not prevent a host activating a declared bus. Support the declared event output on both endpoints; do not hide it or accept activation while discarding its output.

Provide bounded host-owned outputEvents and outputParameterChanges collectors in the Windows process call, serialize their returned values alongside the correlated audio completion through the existing shared-memory mailbox, and deliver them through the current native process callback's SDK sinks. Keep parameter feedback separate from note/MIDI events. Support the pinned SDK Event variants with their real fields, including signed note IDs, bus indices, flags and PPQ; copy bounded text/SysEx payloads while valid, never raw pointers. The engineer chooses the finite capacities, private types and layout and tests refusal at their boundaries; runtime bounds must agree across the negotiated endpoints. No callback allocations, waits, logging or retained host pointers.

Present an event from source position P and vendor offset s at P+s+D, where D is bridge-added delay. Add D once, not vendor latency again; rebase to the actual destination host block and preserve producer order at equal offsets. Keep future events pending. Deliver valid late events once at the earliest legal position in the current/next host callback, in order, and count lateness. Never drop a note-off simply because its accompanying audio expired, replay the request, or kill a healthy instance merely for lateness. Preserve vendor PPQ instead of inventing a time conversion. Process-result delivery must not depend on nonzero audio or a positive frame count; zero-frame parameter flush results need a bounded path to an eligible host callback too.

Null output sinks and inactive buses are legitimate host choices, not transport failure. Record host-unrequested output separately; do not build an unbounded backlog or replay it if a sink later appears. Malformed/oversized results, queue overflow and rejected SDK addEvent/addPoint calls must produce explicit outcomes, not silent success. On terminal failure or stop/reset, use bounded best-effort note release for notes actually handed downstream before discarding future/stale work. Host callbacks that no longer provide a sink cannot be claimed to have received cleanup. Keep generation isolation and AP7 audio-gap behavior.

The return-event policy is our asynchronous bridge decision. It does not claim full MIDI mapping, MPE input, editor gesture forwarding, arbitrary multichannel routing or every VST extension. Existing unsupported auxiliary activation remains explicit. Do not defer a standard return-event variant as another approval task, and do not expand into a general GUI or broker rewrite.
