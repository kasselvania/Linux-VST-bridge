# AP11 — Use the actual vendor editor without disrupting audio

## Outcome and authority

Open the real Serum 2 editor from its bridged Bitwig device, edit a control and an installed preset, record/play back a short automation gesture, save/reopen the sound, and close/reopen the editor without restarting the playing instance. ## Selected design: native entry, detached vendor window, same instance

Return a small native launch/status view through the commercial controller's normal `createView(kEditor)` entry. Reuse the existing X11/host-run-loop approach where useful. It opens/focuses a detached Win32 vendor window on the Deck desktop, created from the SAME Windows `IEditController` already connected to the component producing audio. This is not a second plug-in, vendor standalone app, screenshot editor, or host-window handle passed between incompatible platforms. Full cross-platform embedding is deferred.

On the Windows owner/UI thread, implement the ordinary `IPlugView` lifecycle: query platform support, create the view and local parent, set its `IPlugFrame`, attach using the supported Windows platform type, handle focus/keyboard and sizing constraints, then remove the view before destroying its parent and release it before controller teardown. Respect vendor fixed-size views; basic mouse/keyboard interaction and a usable fit on the actual display are required, not arbitrary resizability. Support the relevant content-scale interface when exposed. Repeated open focuses/reuses one editor per session. Closing the vendor window or removing the native panel closes that view, not the DSP session. Reopening shows the retained sound. Scan/restore alone must not unexpectedly spawn a window.

The existing Windows owner loop services controller/state work but does not pump vendor window messages. `initial_transition`/`next_transition` can block that thread while inactive. Integrate responsive message and control handling while playing, stopped and awaiting lifecycle work; do not require a fake note or a running audio loop to open the editor. Close/unload must cancel pending UI work, finish outstanding gestures where the host is available, and invalidate stale-generation commands before releasing views/controllers. No timer or task may retain a destroyed object.

## Complete the control contract, not just drawing

The standard route is Windows editor `beginEdit/performEdit/endEdit` -> bounded per-session notifications -> native controller/Bitwig component handler on the native UI thread -> host `inputParameterChanges` -> existing Windows processor. Preserve real parameter IDs, gesture order and host automation; do not substitute process-result parameter output for UI gestures, directly invoke host callbacks from a worker, or synthesize a second DSP edit beside the host's returned automation.

In reverse, native `setParamNormalized` and host playback updates must reach the actual Windows controller on its owner thread, without echoing them back as new edits. Coordinate this with AP10's existing processor-to-controller refresh so a stale value does not overwrite a newer accepted update. Refresh preset-changed parameter values and handle the necessary `kParamValuesChanged`, metadata and dirty-state notifications through normal SDK interfaces. Implement the optional handler methods these editors actually use, including grouped gestures where needed; unsupported requests remain explicit, not acknowledged no-ops.

Preserve opaque component/controller state and the existing serialization barrier. Editing while transport is stopped and then saving must capture the applied sound, not a cached Linux slider or pre-edit bundle. Honor host zero-frame parameter flush where applicable. Avoid a save/control path that blocks the native UI thread waiting for work that only that same thread can deliver. Ordinary fixes needed for this sequence are in scope. Preset selection is not permission to silently change unsupported buses or latency.

Reuse the supervised session, generation identity, Rust backend and audio mailbox. A bounded asynchronous UI/control queue or session-bound companion channel is allowed when needed; it is not a new broker or a second audio transport. Choose private representation/capacities as engineering details. Audio must not wait on window servicing, GUI notification acknowledgement or UI queue space. Keep control overload visible without turning it into callback allocation, blocking or hidden buffering. A failed editor-open attempt must leave otherwise healthy audio usable and report its cause.

Publish names from the inspected vendor class metadata, not a Serum/FRAGMENTS name switch. Preserve existing native processor/controller UUID derivation, parameter IDs and saved-project binding. Do not force a user's custom device label to change or promise runtime per-instance renaming in every DAW. Reuse the current prepared-proxy path; a scanner/manager is not needed.
